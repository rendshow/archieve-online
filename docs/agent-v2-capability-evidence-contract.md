# Agent V2 能力与证据契约

> 状态：设计基线 v0.1
> 适用分支：`dev`
> 适用对象：高校档案馆管理人员、学生助理
> 最后更新：2026-07-14

## 1. 文档目的

本文档定义 Agent V2 的能力边界、查询范围、任务结构、证据要求、失败方式和验收标准。后续 Router、检索器、OCR 索引、内容问答和治理检查均必须遵守本契约。

本文档使用以下约束词：

- **必须**：实现和回答不可违反。
- **不得**：明确禁止的行为。
- **应该**：默认实现方式，偏离时必须说明原因。
- **可以**：不影响契约的可选能力。

## 2. 固定前提

### 2.1 文档输入前提

1. 正式档案均为扫描件性质的图片或 PDF。
2. 扫描件默认已经完成图像增强，本 Agent 不调用夸克扫描王或其他图像增强服务。
3. Agent 不考虑可直接提取文本层的普通电子 PDF、Word、Excel 等非扫描文档。
4. PDF 必须按扫描文档处理并建立逐页 OCR 索引；不得因为 PDF 存在少量文本层就跳过扫描页。
5. 原图、原 PDF 是最终凭据，OCR、字段和摘要均是可重建的派生数据。
6. 一份 PDF 可以包含多个材料章节，材料类型必须标注到页或连续页范围，不得把整份 PDF 简化成单一材料类型。
7. 材料章节顺序和页数不得作为固定前提；重复页、无效页、缺失材料和替代性成绩材料都必须允许被显式标注。

### 2.2 权限前提

1. Agent 的档案业务权限永久为只读。
2. Agent 不得创建、修改、移动、重命名、合并、删除档案、文件夹、标签或 OCR 结果。
3. Agent 不得提供任何可绕过只读限制的通用 SQL、文件系统或 MinIO 对象操作工具。
4. 治理能力只能发现问题、解释证据、提出建议，不得执行建议。
5. 会话记录、查询审计、链路追踪和只读分析任务状态属于平台基础设施数据，不视为档案写权限；它们不得反向修改正式档案。

## 3. 核心设计原则

1. **先证据，后表达**：LLM 只能组织工具已经取得的证据，不得凭常识补全档案事实。
2. **能力可组合**：查找、内容分析和治理不是互斥意图，一次请求可以依次调用多种只读能力。
3. **页面范围是硬边界**：Agent 不得查询或引用当前页面授权范围之外的档案。
4. **覆盖率必须可见**：批量查询和统计必须说明总档案数、已索引数、参与计算数和失败数。
5. **不会时明确停下**：范围不清、索引不完整、证据不足或证据冲突时，必须进入对应状态，不得生成貌似完整的回答。
6. **精确检索优先**：姓名、学号、档号、课程、日期等以精确字段和关键词检索为主，语义检索只做补充召回。
7. **过程可审计**：必须保存任务规格、工具调用摘要、证据引用、模型与抽取器版本以及最终状态；不得向用户暴露模型思维链。

## 4. 能力域

Agent V2 包含三个业务能力域。能力域用于产品划分，不用于强迫一条用户消息只能选择一个意图。

### 4.1 文档发现 `DOCUMENT_DISCOVERY`

目标：根据自然语言线索定位一个或多个正式档案。

支持的主要线索：

- 姓名、学号、档号。
- 年份、院系、专业、导师。
- 成绩单、学籍表、学位证、毕业证等材料类型。
- 正文中出现的明确词语或事件。
- 当前馆、当前文件夹、选中文档等页面范围。

完成条件：

- 返回实际存在的档案标识、题名和目录位置。
- 说明每个结果命中了题名、目录、结构化字段还是具体 OCR 页面。
- 结果置信度不足时返回候选并说明差异，不得声称已经找到唯一档案。

以下情况不算完成：

- 仅返回当前目录中无关的前若干份文件。
- 只因为文件名包含姓名，就声称文件内一定包含某类材料。
- 没有结果时编造“可能相关”的档案。

### 4.2 内容智能 `CONTENT_INTELLIGENCE`

目标：基于一个或多个档案的内容提取事实、回答问题、生成表格、筛选和统计。

支持的结果形态：

- 单文档问答。
- 单人跨文档事实汇总。
- 当前范围内的学生名单、材料清单等表格。
- 按字段条件筛选，例如课程成绩、证书日期、导师等。
- 对已结构化事实进行计数、分组和统计。

完成条件：

- 用户要求的每个字段均有页级证据，或被明确标记为未找到、无法识别、存在冲突。
- 表格中的每一行都能回溯到至少一份档案和具体页码。
- 批量结果必须附带覆盖率。
- 日期、成绩和人员身份不得仅从文件创建时间、归档时间或目录名推断。

### 4.3 只读治理 `READ_ONLY_GOVERNANCE`

目标：发现档案质量问题，给出证据和人工处理建议。

MVP 支持：

- 完全重复文件检查。
- 近似扫描内容重复检查。
- 同一人员、同一材料疑似重复录入检查。
- 文件名中的姓名、学号与正文是否一致。
- 无法识别、字段冲突、索引失败等质量问题汇总。

完成条件：

- 返回问题类型、涉及档案、判定依据、置信度和建议。
- 严格区分“完全重复”“疑似重复”和“同一人的不同材料”。
- 不产生任何档案修改操作。

## 5. 查询范围契约

### 5.1 范围类型

- `GLOBAL`：用户位于全局查询页面，按其权限查询全部馆藏。
- `HALL`：限定一个馆。
- `FOLDER_RECURSIVE`：当前文件夹及其全部子目录，作为文件夹页面的默认范围。
- `FOLDER_DIRECT`：只包含当前文件夹直接拥有的文件，不包含子目录；仅在用户明确说“本层”“不含子目录”等词时使用。
- `DOCUMENT`：当前打开的单份档案。
- `SELECTION`：前端明确选中的若干档案。

### 5.2 范围解析优先级

范围按以下顺序收敛，后续步骤只能缩小，不能扩大：

1. 服务端用户权限。
2. 前端传入的页面硬边界。
3. 前端选中对象。
4. 用户本轮明确指定的子范围。
5. 会话中仍位于当前硬边界内的上下文。

### 5.3 页面切换

1. 用户切换馆、文件夹或文档后，前端必须在下一轮请求中传入新的页面上下文。
2. 对话历史可以保留，但旧范围内的档案不得继续作为新问题的证据。
3. 用户通过“刚才那份档案”等表达引用旧结果时，只有该档案仍位于新页面硬边界内才可继续使用。
4. 用户在文件夹页面要求查询上级或全局范围时，返回 `SCOPE_CONFLICT`，提示其切换到对应页面，不得自行扩大范围。
5. “同级文件夹”等表述如果可能指当前层或父目录下的兄弟目录，并且两种解释会产生不同结果，必须澄清。

## 6. 任务契约

### 6.1 不再使用单一意图作为执行依据

单一 `AgentIntent` 只能用于兼容旧接口或统计，不得作为 V2 的核心执行模型。V2 必须把用户请求解析为结构化 `AgentTaskSpec`，并允许一个请求生成多个步骤。

建议的数据结构：

```json
{
  "capability": "CONTENT_INTELLIGENCE",
  "operations": [
    "RESOLVE_SUBJECT",
    "LOCATE_DOCUMENTS",
    "READ_FACTS",
    "ANSWER"
  ],
  "scope": {
    "type": "FOLDER_RECURSIVE",
    "hallId": 1,
    "folderPath": "西区硕博学籍学位档案"
  },
  "subjectFilters": {
    "personName": "李二牛"
  },
  "documentFilters": {
    "materialTypes": ["TRANSCRIPT", "DEGREE_CERTIFICATE"]
  },
  "requestedFields": [
    "COURSE_GRADE:高等数学",
    "DEGREE_CERTIFICATE_DATE"
  ],
  "predicates": [],
  "groupBy": [],
  "outputType": "TEXT",
  "evidenceRequirement": "PAGE_LEVEL"
}
```

### 6.2 允许的操作

- `LOCATE_DOCUMENTS`：定位档案。
- `RESOLVE_SUBJECT`：识别并区分学生实体。
- `SEARCH_PAGES`：检索 OCR 页面和片段。
- `READ_FACTS`：读取已经抽取的结构化事实。
- `EXTRACT_FIELDS`：从已选定页面临时提取指定字段。
- `BUILD_TABLE`：生成结构化表格数据。
- `FILTER_FACTS`：按条件筛选事实。
- `AGGREGATE_FACTS`：计数、分组、统计。
- `AUDIT_DUPLICATES`：检查重复档案。
- `AUDIT_IDENTITY_CONSISTENCY`：检查姓名、学号和文件名一致性。
- `ANSWER`：根据已通过证据门禁的数据生成回答。

不存在 `MOVE`、`RENAME`、`DELETE`、`MERGE`、`UPDATE` 等写操作。

### 6.3 任务解析规则

1. 明确的帮助、空消息、越权和写操作请求可以由规则层直接处理。
2. 一般自然语言由 LLM 解析为受 JSON Schema 约束的 `AgentTaskSpec`。
3. Schema 校验器必须检查操作白名单、范围、字段、数据类型和必要参数。
4. Planner 根据有效 TaskSpec 生成有限步骤的执行计划。
5. Executor 只执行注册过的只读工具，不接受模型生成的 SQL、URL、对象路径或 Java 表达式。
6. 同步任务应限制最大步骤和候选数量；超出限制时转为只读后台分析任务并返回 `QUERY_QUEUED`。
7. LLM 不得跳过工具执行直接生成档案事实。

## 7. 只读工具契约

| 工具 | 输入 | 输出 | 主要约束 |
|---|---|---|---|
| `ScopeResolver` | 页面上下文、用户表达 | 规范化范围 | 只能缩小页面硬边界 |
| `IndexCoverageReader` | 范围 | 索引总量和状态分布 | 只读，不自动创建索引任务 |
| `DocumentSearchTool` | 范围、线索、过滤条件 | 文档候选及命中依据 | 支持精确、全文和语义召回 |
| `PageSearchTool` | 范围、关键词、字段线索 | 页级 OCR 片段 | 必须返回文档 ID 和页码 |
| `SubjectResolver` | 姓名、学号、候选文档 | 人员候选 | 同名人员不得自动合并 |
| `FactQueryTool` | 人员、字段、材料类型 | 结构化事实 | 必须携带证据引用 |
| `TargetedExtractionTool` | 已选页面、字段定义 | 临时字段结果 | 不能扫描未入选的全量文档 |
| `AggregationTool` | 事实、条件、分组 | 表格或统计 | 必须计算覆盖率和未识别数量 |
| `DuplicateAuditTool` | 范围、阈值 | 重复候选组 | 同人不同材料不能判为重复 |
| `IdentityConsistencyTool` | 范围 | 一致、疑似不一致、不可核验 | 必须对比文件名与正文证据 |

所有工具必须通过后端服务层访问数据，不向 LLM 暴露数据库连接、MinIO 凭证或实际存储路径。

## 8. OCR 与知识索引契约

### 8.1 统一索引链路

新旧正式档案必须进入同一条可重建链路：

```text
正式档案
  -> 文件指纹校验
  -> 图片或 PDF 逐页展开
  -> 全页 OCR
  -> 版面与表格识别
  -> 页级文本分块
  -> 人物、材料类型和常用字段抽取
  -> 全文索引与结构化事实索引
```

### 8.2 强制要求

1. 默认输入已经增强，索引链路不得再次调用图像增强 API。
2. PDF 必须覆盖全部页面，不得只处理前几页。
3. 每页必须保留页码、OCR 文本、文本块坐标、OCR 置信度和处理版本。
4. 成绩单必须保留表格行列关系，不能只保存打平后的全文。
5. 同一文件在内容哈希和 OCR 版本均未变化时不得重复 OCR。
6. OCR 失败必须记录在页级和文档级状态中，不得写入空文本后伪装为索引完成。
7. OCR 质量不足时标记为 `PARTIAL` 或 `FAILED`，Agent 返回证据不足；不得自动调用图像增强兜底。

### 8.3 索引状态

- `NOT_INDEXED`：尚未进入索引链路。
- `QUEUED`：等待后台处理。
- `OCR_RUNNING`：正在逐页 OCR。
- `EXTRACTING`：正在抽取结构化字段。
- `READY`：全部页面和必要字段处理完成。
- `PARTIAL`：部分页面或字段失败，但存在可用证据。
- `FAILED`：没有形成可用索引。
- `STALE`：原文件或处理版本变化，需要重建。

Agent 只能读取这些状态。索引任务的创建、重试和管理由独立的后台管理接口负责。

### 8.4 数据职责

- MySQL：正式档案元数据、人员实体、结构化事实、索引任务状态、会话和审计记录。
- MinIO：原文件、必要的页面派生图和完整 OCR JSON。
- OpenSearch：页级全文、检索字段、过滤字段和可选向量。
- RabbitMQ：OCR、字段抽取、索引重建和只读批量分析任务。

OpenSearch 是可重建的派生索引，不是档案事实的最终来源。MySQL 和 MinIO 中的正式档案及证据引用是最终依据。

### 8.5 首批结构化事实

| 字段 | 说明 |
|---|---|
| `PERSON_NAME` | 学生姓名，保留原文和规范值 |
| `STUDENT_NO` | 学号 |
| `MATERIAL_TYPE` | 成绩单、学籍表、学位证、毕业证等 |
| `COURSE_NAME` | 课程名称，保留原始名称和规范名称 |
| `COURSE_GRADE` | 成绩原值、规范值和单位/等级 |
| `ADVISOR_NAME` | 导师姓名 |
| `DEGREE_AWARD_DATE` | 学位授予日期 |
| `DEGREE_CERTIFICATE_DATE` | 学位证书上明确记载的日期 |
| `GRADUATION_CERTIFICATE_DATE` | 毕业证书上明确记载的日期 |

三类日期不得相互替代。归档时间、文件创建时间和目录年份不得作为上述日期的证据。

## 9. 人员实体契约

1. 优先使用学号识别同一学生。
2. 学号缺失时，可以综合姓名、院系、专业、年份和材料关联生成候选，但必须保留不确定性。
3. 同名且缺乏唯一标识的人员不得自动合并。
4. 姓名 OCR 出现相近字时，只能作为候选，不得静默纠正为另一人。
5. 人员列表去重应优先按学号，其次按已确认的人员实体；只按姓名去重时必须提示可能存在同名。

## 10. 证据契约

### 10.1 证据类型

- `METADATA`：档案 ID、题名、档号、目录、格式、页数。
- `OCR_PAGE_TEXT`：具体扫描页上的 OCR 文本和坐标。
- `STRUCTURED_FACT`：从某页提取并规范化的字段。
- `BINARY_FINGERPRINT`：文件哈希、页面感知哈希等技术指纹。
- `DERIVED_COMPARISON`：由两个或多个证据计算的一致性、重复度或统计结果。

### 10.2 证据记录最小字段

```json
{
  "evidenceId": "ev-01",
  "type": "STRUCTURED_FACT",
  "documentId": 123,
  "documentTitle": "2014-JX14-32包英夫",
  "pageNo": 4,
  "boundingBox": [120, 340, 860, 410],
  "quote": "高等数学 92",
  "rawValue": "92",
  "normalizedValue": "92",
  "ocrConfidence": 0.97,
  "extractionConfidence": 0.95,
  "extractorVersion": "fact-extractor-v1",
  "sourceChecksum": "sha256:..."
}
```

### 10.3 不同能力的最低证据

| 结论 | 最低证据要求 |
|---|---|
| 某档案存在及其位置 | `METADATA` |
| 某词出现在档案正文 | `OCR_PAGE_TEXT` |
| 某人的课程成绩或证书日期 | `STRUCTURED_FACT` 或带页码的定向提取结果 |
| 当前范围的人员名单 | 每名人员至少一个姓名事实和来源档案 |
| 条件筛选和统计 | 每个入选项都有满足条件的字段证据，同时报告覆盖率 |
| 文件完全重复 | 相同内容哈希，并核对文件大小 |
| 文件疑似重复 | 页面指纹、OCR 相似度和人员/材料信息中的至少两类证据 |
| 文件名与正文不一致 | 文件名解析结果与正文姓名/学号事实的明确冲突 |

`aiSummary` 只能辅助召回和阅读，不得单独证明姓名、成绩、导师、材料类型或日期等精确事实。

### 10.4 置信度不得混为一个数字

系统必须分别记录：

- 检索相关度。
- OCR 置信度。
- 字段抽取置信度。
- 人员归并置信度。
- 索引覆盖率。
- 证据冲突状态。

最终回答可以给出“高、中、低”的用户可读结论，但后端不得用一个总分掩盖某个环节的不确定性。

## 11. 可回答性门禁

### 11.1 返回状态

- `COMPLETED`：用户要求的全部内容均有充分证据。
- `PARTIAL`：仅部分字段有充分证据，必须逐项说明缺失内容。
- `NEEDS_CLARIFICATION`：存在会实质改变查询结果的歧义。
- `SCOPE_CONFLICT`：用户要求的范围超出页面硬边界。
- `INDEX_INCOMPLETE`：当前索引覆盖不足，无法可靠完成任务。
- `INSUFFICIENT_EVIDENCE`：索引存在，但证据不能支持结论。
- `QUERY_QUEUED`：只读批量分析已进入后台队列。
- `FAILED`：工具或模型调用失败，且没有可靠的降级结果。

### 11.2 门禁规则

1. 只有 `COMPLETED` 和 `PARTIAL` 可以生成事实性正常回答。
2. 内容问题没有页级证据时，不得把无关档案列表包装成候选答案。
3. 批量表格和统计必须提供 `totalDocuments`、`indexedDocuments`、`examinedDocuments`、`matchedDocuments` 和 `failedDocuments`。
4. 证据冲突时必须展示冲突值及各自来源，不得让 LLM 擅自选择一个。
5. OCR 没有识别到目标字段，只能表达“当前可用证据未识别到”，不得表达“该学生没有该字段或材料”。
6. 不得根据常识推断扫描件中没有明确记载的内容。
7. 澄清问题每轮最多提出一个，并优先询问最影响执行计划的歧义。

## 12. 响应契约

### 12.1 结构化响应

建议的 `AgentResponseV2`：

```json
{
  "requestId": "req-01",
  "sessionId": 10,
  "status": "COMPLETED",
  "answer": "在当前文件夹中找到李二牛，高等数学成绩为 92 分。",
  "scope": {
    "type": "FOLDER_RECURSIVE",
    "displayName": "西区硕博学籍学位档案"
  },
  "coverage": {
    "totalDocuments": 120,
    "indexedDocuments": 120,
    "examinedDocuments": 2,
    "matchedDocuments": 2,
    "failedDocuments": 0
  },
  "resultType": "TEXT",
  "data": {},
  "evidence": [
    {
      "evidenceId": "ev-01",
      "type": "STRUCTURED_FACT",
      "documentId": 123,
      "pageNo": 4,
      "quote": "高等数学 92",
      "normalizedValue": "92"
    }
  ],
  "warnings": [],
  "traceId": "trace-01"
}
```

### 12.2 结果类型

- `TEXT`：简短事实回答。
- `DOCUMENT_LIST`：档案定位结果。
- `TABLE`：学生名单、成绩、日期筛选等结构化表格。
- `GOVERNANCE_REPORT`：重复和一致性问题报告。

表格必须作为列定义和行数据返回，由前端渲染；不得依赖 LLM 生成 Markdown 表格。每一行应携带自己的证据引用。

### 12.3 SSE 事件

- `meta`：请求 ID、规范化范围、任务类型。
- `progress`：只读批量分析进度。
- `delta`：文本回答增量。
- `result`：最终结构化数据和证据。
- `done`：最终状态。
- `error`：可展示错误，不包含密钥、SQL、存储路径或模型思维链。

前端不得向普通用户展示 Router 候选分数、内部提示词或“思考链路”。调试信息通过 `traceId` 在管理端查询。

## 13. 典型场景验收

### 13.1 根据线索找档案

问题：“帮我找包英夫的成绩单。”

必须：

- 在硬范围内解析人员姓名和材料类型。
- 同时检索题名、结构化人员事实、材料类型事实和 OCR 页面。
- 返回最相关档案及命中依据。

不得：仅因题名含“包英夫”就断言该文档一定是成绩单。

### 13.2 生成当前文件夹学生名单

问题：“汇总当前文件夹中的学生姓名，给我一张表。”

必须：

- 默认查询当前文件夹及子目录。
- 按学号优先去重。
- 返回姓名、学号、来源档案、识别状态和证据。
- 报告索引覆盖率和无法确认身份的档案数量。

### 13.3 查询一个人的跨文档事实

问题：“当前文件夹有没有李二牛？有的话告诉我高等数学成绩，以及他几月份拿到学位证书。”

执行计划至少包含：

1. 在范围内识别李二牛对应的人员实体。
2. 定位其成绩单和学位证书材料。
3. 提取高等数学成绩。
4. 提取学位证书上明确记载的日期。
5. 检查两个事实是否属于同一人员。
6. 返回答案及两处页级证据。

如果扫描件只有学位授予日期、没有证书日期，必须说明字段差异，不得替换概念。

### 13.4 日期条件筛选

问题：“统计当前文件夹中 9 月之后才拿到毕业证的有谁？”

必须：

- 使用 `GRADUATION_CERTIFICATE_DATE`。
- 明确“9 月之后”为月份 10 至 12；不得把 9 月包含在内。
- 返回姓名、日期、档案和页码。
- 将日期不可识别的人员列入未参与统计数量。

不得使用归档时间、文件修改时间或目录年份代替证书日期。

### 13.5 重复录入检查

问题：“当前文件夹有没有重复录入同一个人的材料？”

必须分层返回：

- 完全重复文件。
- 高置信度近似扫描重复。
- 同一人员同一材料疑似重复。
- 同一人员的不同材料，不属于重复。

结果只能给出人工复核建议，不得产生删除、合并或移动操作。

### 13.6 文件名一致性检查

问题：“检查这批材料的姓名、学号和文件名是否一致。”

每份档案只能进入以下状态之一：

- `CONSISTENT`：文件名和正文事实一致。
- `SUSPECTED_MISMATCH`：存在明确冲突并提供双方证据。
- `UNVERIFIABLE`：文件名或正文缺少可比较字段。

“无法识别”不得算作“不一致”。

## 14. 非目标

Agent V2 当前不负责：

- 图像增强和扫描质量修复。
- 档案录入、命名、标签生成和审核入库。
- 任何形式的档案写操作。
- 自动认定缺失材料具有法律或行政效力。
- 没有证据支持的开放领域知识问答。
- 让 LLM 直接遍历数据库、MinIO 或全部原始文件。
- 用向量相似度替代精确姓名、学号、成绩和日期判断。

## 15. 安全与审计

1. Agent 工具使用独立的只读服务接口和最小权限账号。
2. 每次查询必须记录用户、页面范围、TaskSpec 摘要、工具名称、档案 ID、证据 ID、最终状态和耗时。
3. 日志不得记录模型密钥、MinIO 凭证和完整敏感正文。
4. 用户只能看到其档案权限范围内的结果和证据。
5. 工具输出中的存储路径必须转换为受权限控制的档案预览地址。
6. Agent 收到移动、重命名、删除、合并等要求时，明确说明自身只读，并可给出人工检查建议。

## 16. 质量评估与发布门槛

### 16.1 基准集

必须建立人工标注的增强扫描件基准集，至少覆盖：

- 姓名、学号、档号查找。
- 材料类型查找。
- 成绩单表格抽取。
- 学位证和毕业证日期抽取。
- 单人跨文档问答。
- 文件夹人员名单。
- 日期条件筛选和统计。
- 完全重复、近似重复和非重复样本。
- 文件名一致、不一致和不可核验样本。
- 索引不完整、OCR 失败和证据冲突样本。

每条用例至少标注：页面范围、期望 TaskSpec、目标档案、目标字段、页码证据和期望返回状态。

### 16.2 核心指标

- 文档定位 `Recall@5`。
- 文档定位 `Top1 Accuracy`。
- 姓名、学号、课程、成绩和日期字段准确率。
- 表格行精确率和召回率。
- 证据引用正确率。
- 正确拒答率和错误拒答率。
- 重复检查精确率。
- 文件名一致性检查精确率。
- 索引覆盖率报告准确率。

### 16.3 MVP 发布门槛

1. 文档定位 `Recall@5 >= 95%`。
2. 表格有效行精确率 `>= 97%`。
3. 重复和不一致问题的精确率 `>= 95%`，优先降低误报。
4. 抽样回答中的事实必须有正确证据引用，证据支持率为 `100%`。
5. 索引不完整或证据不足时，正确进入非完成状态的比例 `>= 95%`。
6. 发现任何无证据编造姓名、成绩、日期或材料结论，视为阻断发布的问题。
7. 验证 Agent 工具集中不存在档案写工具，并通过越权与写请求测试。

初次基准测试如果无法达到门槛，应保留实际基线并针对 OCR、字段抽取、检索或门禁分别优化，不得仅通过修改回答提示词掩盖问题。

## 17. 代码重整边界

### 17.1 可以保留

- Agent Controller、会话和 SSE 传输骨架。
- 页面上下文和馆/文件夹/文档范围模型。
- RabbitMQ、MinIO 和正式档案目录结构。
- 外部模型的 OpenAI-Compatible 调用适配层。

### 17.2 需要替换或演进

- 关键词主导的单一意图 Router，替换为 TaskSpec 语义解析和 Schema 校验。
- `AgentChatServiceImpl` 中按单一枚举分支的执行方式，替换为 Planner 和只读 Executor。
- MySQL `LIKE` 加固定候选上限的检索器，替换为精确字段与全文检索组合。
- `archive_document.ocr_text` 整文档大字段，演进为页级 OCR、结构化事实和可重建索引。
- 仅返回文本的响应，演进为文本、文档列表、表格和治理报告的统一结构化协议。

### 17.3 实施顺序

1. 建立基准集和自动评测骨架。
2. 建立页级 OCR、表格结构和结构化事实模型。
3. 引入全文索引，先完成文档发现。
4. 实现 TaskSpec、Planner、只读工具和证据门禁。
5. 完成学生名单、单人跨文档字段查询和日期筛选。
6. 完成只读重复检查和文件名一致性检查。
7. 用基准集验收后切换 Agent V2，旧意图接口只保留兼容适配层并逐步下线。

## 18. Agent V2 总体验收定义

Agent V2 只有同时满足以下条件才算完成：

1. 用户可以在授权范围内稳定定位档案。
2. 用户可以获得带页级证据的单文档和跨文档内容回答。
3. 用户可以获得带覆盖率和逐行证据的结构化表格与统计结果。
4. 用户可以执行只读重复和一致性检查，但 Agent 无法修改任何档案。
5. 范围冲突、索引不完整、证据不足和证据冲突均有明确、简短且不误导的返回状态。
6. Agent 的正常回答中不存在无证据档案事实。
